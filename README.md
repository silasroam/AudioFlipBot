# Audio Converter Bot (Pyrogram / MTProto, файлы до 2000 МБ)

Telegram-бот-конвертер: принимает аудио, голосовые, видеосообщения (кружочки), видео и файлы
**до 2000 МБ**, показывает инлайн-кнопки **MP3 / OGG Voice / WAV / M4A**, отдаёт результат и
всегда удаляет временные файлы из `downloads/`.

Стек: **Pyrogram 2.x (MTProto) + системный ffmpeg**. Никаких БД, брокеров и докера — 2 файла
кода (`bot.py`, `converter.py`).

## Зачем Pyrogram, а не aiogram

| | Bot API (aiogram) | MTProto (Pyrogram) |
|---|---|---|
| Скачать от пользователя | максимум **20 МБ** | до **2000 МБ** |
| Отправить результат | максимум **50 МБ** | до **2000 МБ** |

Bot API физически не отдаёт боту большие файлы, поэтому для 2 ГБ нужен клиентский API.
Скачивание идёт chunk-by-chunk прямо в файл на диске (Pyrogram: `handle_download` открывает
файл в `"wb"` и пишет каждый полученный чанк), поэтому оперативная память остаётся низкой —
это критично для Render с 512 МБ RAM.

## Установка

```bash
sudo apt install ffmpeg        # Debian/Ubuntu (macOS: brew install ffmpeg)

python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` ставит `kurigram` (maintained-форк Pyrogram, тот же API и импорт `pyrogram`)
и `tgcrypto`. Официальный `pyrogram==2.0.106` устарел: на Python 3.13+ он даже не
импортируется (`pyrogram/sync.py` вызывает удалённый `asyncio.get_event_loop()`), поэтому
форк — единственный вариант, который работает и на 3.10–3.12, и на 3.13/3.14.

## Запуск

**В проекте нет ни токена, ни `api_id`/`api_hash`** — папку можно публиковать как есть.
Секреты берутся снаружи, в таком порядке:

1. переменные окружения `API_ID`, `API_HASH`, `BOT_TOKEN` — так делается на Render;
2. скрытые файлы рядом с `bot.py`: `.api_id`, `.api_hash`, `.bot_token` (по одному значению
   в файле) — удобно локально. Они в `.gitignore` и в репозиторий не попадают.

Если ничего не задано, бот не стартует и печатает, чего именно не хватает:

```
Не заданы: API_ID, API_HASH, BOT_TOKEN. Задай их переменными окружения или файлами .api_id / .api_hash / .bot_token рядом с bot.py
```

### Локально (любой из вариантов)

```bash
# вариант 1: переменные окружения на текущую сессию
export API_ID=твой_api_id API_HASH=твой_api_hash BOT_TOKEN=12345:AA...
python bot.py

# вариант 2: скрытые файлы (живут только локально, в git не попадут)
printf '%s\n' 'твой_api_id'   > .api_id
printf '%s\n' 'твой_api_hash' > .api_hash
printf '%s\n' '12345:AA...'   > .bot_token
chmod 600 .api_id .api_hash .bot_token
python bot.py
```

### Render

Settings → **Environment** → *Environment Variables* (значения берутся из @BotFather и
my.telegram.org; в коде и в репозитории их нет):

| Key | Пример значения |
|---|---|
| `API_ID` | `12345678` (число из my.telegram.org) |
| `API_HASH` | `0123456789abcdef0123456789abcdef` (32 символа) |
| `BOT_TOKEN` | `12345678:AA...` (от @BotFather) |

Тип сервиса — **Web Service** (Free). Render сканирует открытые порты и без них убивает
сервис с ошибкой `No open ports detected`, поэтому бот дополнительно поднимает мини-HTTP-сервер
на `0.0.0.0:$PORT` (Render подставляет `PORT` сам; локально по умолчанию `10000`) с маршрутами
`/` и `/health` → `200 OK`. На работу бота это не влияет, новых переменных окружения задавать
не нужно.

Start Command: `python bot.py`. Диск на Render эфемерный, поэтому файл сессии
`audio_converter_bot.session` пересоздаётся при каждом деплое — бот просто логинится заново
по `BOT_TOKEN` (никаких SMS/паролей боту не требуется). Если сессия окажется отозванной
(например, сменили токен у @BotFather — `/revoke` убивает все сессии), бот сам удалит её и
переавторизуется: в логе будет `⚠️ Сессия недействительна (SessionRevoked) — удаляю её и логинюсь заново`.

### Что никогда не коммитить

`.bot_token`, `.api_id`, `.api_hash`, `.env`, любые `*.session` — они уже в `.gitignore`.
Файл `.session` — это фактически ключ доступа к боту, он не менее секретный, чем токен.

## Файлы

| Файл | Назначение |
|---|---|
| `bot.py` | клиент Pyrogram, хендлеры, прогресс, регистрация хендлеров, очистка |
| `converter.py` | сборка команды ffmpeg + асинхронная конвертация (`asyncio.create_subprocess_exec`) |
| `downloads/` | временная папка (создаётся сама, чистится после каждой задачи и при старте) |
| `.venv/`, `*.session` | локальное окружение и сессия — в `.gitignore` |

## Деплой на Render (512 МБ RAM)

- **RAM**: скачивание/загрузка стримятся на диск, в памяти держатся только метаданные и
  по 1–2 МБ чанка. ffmpeg тянет ~30–80 МБ на аудио-задачу. Итог — заметно ниже 512 МБ.
- **Диск**: нужен запас `вход + выход`. Для WAV (несжатый) выход может быть больше входа,
  так что для 2 ГБ-входа берите инстанс с 5+ ГБ диска, иначе упадёт на переполнении.
- **Очередь**: конвертации выполняются по одной (`asyncio.Semaphore(1)` в `converter.py`),
  остальные пользователи ждут — это осознанно, чтобы не убить CPU/RAM бесплатного тарифа.
- **Таймаут ffmpeg**: по умолчанию 2 часа, меняется переменной `FFMPEG_TIMEOUT` (секунды).
- **Долгие задачи**: Render перезапускает сервис при деплое, задача из памяти пропадёт
  (`PENDING` живёт в RAM) — пользователь получит «Кнопка устарела, пришли файл заново».

## Что важно знать

- Файлы больше 2000 МБ бот скачать не может (предел MTProto) — такие отклоняются сразу
  с понятным сообщением.
- Голосовое сообщение = OGG/Opus (кнопка «OGG (голосовое)»).
- Задачи в памяти, БД нет: после рестарта старые кнопки дают алерт и просят прислать файл заново.
- Больше 2000 МБ технически требует Telegram Premium-аккаунта (4 ГБ), боту это недоступно.

## Управление (локально)

```bash
# запуск в фоне
nohup .venv/bin/python -u bot.py > bot.log 2>&1 &
tail -f bot.log

# остановить
pkill -f "bot.py"
```
